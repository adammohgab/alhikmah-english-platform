# 09. SEED DATA

The frontend develops against a REAL dev backend with REAL seeded data (no mocks). The seed makes every page in the specs demonstrable with realistic content, every state reachable, and every flow testable.

---

## 1. SEED LAYERS

| Layer | Environments | Purpose |
|---|---|---|
| System seed | every environment including production | Data the product cannot run without |
| Demo seed | local, dev (and staging if created) | A believable school with history for every page and state |
| E2E fixtures | local and CI | A small deterministic subset with fixed ids used by Playwright and contract tests |
| Load seed | a separate load-test project only | Generated volume (2,500 users, millions of ledger rows) |
Commands (in `backend/scripts`): `seed:system`, `seed:demo`, `seed:e2e`, `seed:load`, `seed:reset` (dev only: truncates then reseeds), `seed:advance --days N` (dev only: moves time-relative data forward so pages stay "alive"). Seeds are idempotent (upserts by stable keys) and never run against production except `seed:system` on first setup.

---

## 2. SYSTEM SEED (REQUIRED EVERYWHERE)
- `platform_settings`: defaults for all keys (platform name "Wordland", region with the school time zone placeholder, features all enabled, preferences, security defaults, maintenance off, data retention keys null).
- `config_sets` (published version 1): `economy` (docs/shared/ECONOMY-AND-GAMES.md values and the materialized level table), `ai_features` (all enabled), `ai_limits` (AI-BEHAVIOR defaults: student 40, 10, 3; teacher 400 credits; budget placeholder), `ai_safety` (Strict for students), `ai_instructions` (empty school text plus feature add-on stubs).
- `games`: the seven games with reference scores and per-difficulty config.
- `quest_templates`: the 16 daily and 6 weekly templates (published).
- `badge_definitions`: the 40 starter badges (published), with icons from `public-assets`.
- Shop: free starters (themes Candy Pop and Sorbet; 6 base characters; 7 rank frames), purchasable catalog (8 themes with tokens verified by the contrast checker; 20 outfits, 16 accessories, 12 backgrounds; 14 frames; 24 titles; power-ups; price bands per rarity). Art files are placeholders until final art arrives (a file per item is required so pages render).
- Default rubrics (the five-criteria writing rubric) and the default `ai_test_cases` (30 starter cases).
- One school year with terms and the first Super admin account created from environment variables (`BOOTSTRAP_ADMIN_USERNAME`, a one-time password printed once and forced to change).

## 5. DEMO SEED: ACTIVITY AND STATES

### 5.1 Learning and assessment
- Lesson and activity progress consistent with each student's level and streak.
- Quizzes: draft, scheduled, open (some students mid-attempt), closed with full attempt histories, retakes allowed, extra attempts granted, auto-submitted attempt, one student with attempts exhausted.
- Assignments: draft; open with every submission state (not started, in progress with a draft, submitted awaiting, AI graded, flagged by AI, graded not released, released, late with penalty); one per grading mode (review each, overall, bulk with a mix of eligible and flagged, manual); a closed one; a not-accepted-late example.
- AI-graded writing samples with scores, confidence and flags; grade history entries including an override and a penalty override.
- Unlock overrides: one open early, one locked until a date, one scheduled release.

### 5.2 Gamification
- XP and coin ledgers generated from the seeded activity with realistic caps, so `student_stats` equals the ledger sums.
- Quests for today and this week in every state (in progress, ready, claimed, expired yesterday), chests claimed and unclaimed, class quests (active, ended, manual awaiting confirmation).
- Badges earned in every category and rarity with progress rows; secret badges earned by a few.
- Leaderboard history: four weeks of ledger activity per student, weekly snapshots for the last three weeks, a hidden student, a reset-score row, two open flags (XP spike and display name).
- Game sessions: a few hundred across all seven games with personal bests; one rejected session (impossible log).
- Shop: purchases and inventories at varied levels, sales active and expired, a retired item still owned, limited-time item, bundle.
- Certificates: course completion, rank, streak.

### 5.3 Communication
Announcements in every state (draft, scheduled, normal, important, urgent active, expired) with read counts; notifications of every kind for the named accounts (read and unread); class invite pending for `student.new`.

### 5.4 AI
- Tutor conversations in all four modes, including a blocked message (neutral reply), a repeated block (flagged conversation), a hint-only exchange, a thumbs-down.
- Copilot conversations with cards in every status (ready, approved, edited, discarded, failed, stale).
- Jobs: succeeded course generation, running (progress 5 of 8), failed (with a failed step), queued, canceled.
- Usage for 60 days across features and roles so the admin charts, forecast and top consumers look real, with month-to-date at about 68 percent of the placeholder budget and one anomaly spike; limit-hit records.
- Test cases with last results (two failing so the failure UI can be seen).

### 5.5 Admin and operations
Moderation items (new, in review, resolved, dismissed; all three types; Low, Medium, High), password reset requests (new, handled, dismissed), an import job at the validation step with errors and warnings, a planned (not executed) rollover, an executed rollover from last year with undo available, audit entries of every category, platform settings changes with versions, config versions (economy v1 published, v2 draft), a theme draft failing contrast, a maintenance-off state.

## 6. E2E FIXTURES
A deterministic subset (`seed:e2e`) with fixed UUIDs, small enough to reset in seconds: 1 school year, 2 classes, 2 teachers (one co-teaching), 6 students (new, mid, at-risk, locked, first-login, archived), 1 admin of each level, 1 official course with 2 units, 1 quiz (open, 5 questions of all types), 1 assignment per grading mode, quests and badges, shop items of each kind, and the AI adapter set to the deterministic fake. The Playwright flows listed in frontend/docs/ARCHITECTURE.md section 9 and the contract tests run against this fixture.

---

## 7. LOAD SEED
A generator creates 2,500 users, 120 classes, 5 million ledger rows, 2 million attempts and answers, 500,000 notifications and 300,000 AI usage rows with realistic distributions, in a separate Supabase project, to validate RLS performance, indexes and dashboards (12-TESTING.md).

---

## 8. SEED VERIFICATION
`seed:verify` asserts the invariants of 06-BUSINESS-LOGIC.md section 16 (ledger sums match stats, no negative coins, one published snapshot per entity, every class has a teacher, no student can read another's rows) and that every page in the frontend specs has at least one account and one record that exercises it (a manifest `seed/page-coverage.yml` maps page ids ST-, TC-, AD-, SH- to the accounts and records). CI fails if a page has no coverage entry.

---

## 9. CONTENT QUALITY
Seed content is real school English at the right level (written and reviewed once, possibly drafted with the AI pipeline and then edited), no lorem ipsum, no placeholder names such as "Item 1". Arabic meanings are correct and reviewed. Images and audio are licensed or generated for this project and listed in `seed/content/ATTRIBUTIONS.md`.
